# Working Agreement

This is a documentation repository rather than a software project. Keep contributions concise, evidence-based, and easy to trace.

## Weekly Workflow

1. The supervisors prepare `weekly/week-XX/assignment.md`.
2. The student completes `student-response.md` before the stated meeting.
3. The supervisors record comments and decisions in `supervisor-feedback.md`.
4. The meeting outcome and assigned actions are recorded in `meeting-notes.md`.
5. Confirmed project-level decisions are copied to `project-records/decision-log.md`.

Create a new week by copying the complete `weekly/_template/` directory. Keep the four standard filenames unchanged.

## Editing Rules

- Edit your designated document instead of overwriting another contributor's text.
- Distinguish published evidence, interpretation, assumptions, and open questions.
- Cite papers with a DOI or stable publisher link.
- Link to papers instead of uploading copyrighted PDFs.
- Use tables for comparisons when several mechanisms or actuators are evaluated against the same criteria.
- Record meaningful updates in separate commits with short messages such as `Add Week 2 assignment` or `Complete Week 2 response`.
- Do not commit personal data, credentials, payment details, or confidential laboratory information.

## File Formats

Use Markdown for routine documentation. PDF, image, spreadsheet, CAD, quotation, and receipt files may be added only when they are needed and only after the repository is private.
